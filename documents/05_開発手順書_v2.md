# CUIオセロ v2.0 開発手順書

本ドキュメントは、CUIオセロアプリケーションのバージョン2.0開発における全手順を詳細に記録するものである。この手順に従うことで、誰でもv2.0の開発プロセスを完全に再現できることを目指す。

## 1. 全体計画

1.  **開発手順書の作成と計画の記述**:
    *   今回の開発作業（v2.0）の全手順を記録するための `documents/05_開発手順書_v2.md` を作成する。（←イマココ）

2.  **クリーンアーキテクチャへのリファクタリング**:

3.  **ヒント表示機能の実装**:

4.  **コンピュータ対戦機能の実装**:

5.  **最終化とドキュメントの完成**:

## 2. 開発ログ

### 2.1. クリーンアーキテクチャへのリファクタリング

- **目的**: 既存コードの責務を分離し、今後の機能追加を容易にするため。
- **手順**:
  1.  `mkdir -p othello/entities othello/use_cases othello/interface_adapters` を実行し、各レイヤーのディレクトリを作成した。
  2.  `touch othello/entities/__init__.py othello/use_cases/__init__.py othello/interface_adapters/__init__.py` を実行し、Pythonパッケージとして認識させた。
  3.  `mv othello/core.py othello/entities/game.py` を実行し、データ構造をEntityレイヤーに移動した。
  4.  `mv tests/test_core.py tests/test_use_cases.py` を実行し、テストファイル名を新しい構造に合わせた。
  5.  `othello/use_cases/game_logic.py` を新規作成し、`othello/entities/game.py` からビジネスロジック（`create_initial_state`, `handle_move`など）をすべて移動させた。
  6.  `othello/entities/game.py` を編集し、データ構造の定義（`GameState`, `Player`など）のみが残るようにした。
  7.  `tests/test_use_cases.py` と `main.py` のインポート文を `from othello import core` から `from othello.use_cases import game_logic as core` など、新しいパスに修正した。
  8.  `pytest` を実行し、リファクタリング後も5つのテストがすべて成功することを確認した。

### 2.2. ヒント表示機能の実装

- **目的**: プレイヤーが現在石を置ける場所の一覧を表示する機能を追加する。
- **手順**:
  1.  **TDD (Test)**: `tests/test_use_cases.py` に `test_get_valid_moves` を追加。初期盤面で黒が置ける4つの手を正しく取得できるか検証するテストを記述した。
  2.  `pytest` を実行し、`get_valid_moves` が未実装なため `AttributeError` でテストが失敗することを確認した (レッド)。
  3.  **TDD (Develop)**: `othello/use_cases/game_logic.py` に `get_valid_moves` 関数を実装。盤面を走査し、`is_valid_move` が `True` を返す座標をリストアップするロジックを記述した。
  4.  `pytest` を実行し、`test_get_valid_moves` を含む6つのテストがすべて成功することを確認した (グリーン)。
  5.  **CUI統合**:
      - `othello/entities/game.py` の `GameState` に `show_hints: bool = False` 属性を追加した。
      - `main.py` の `render_view` を修正。`state.show_hints` が `True` の場合に、`get_valid_moves` の結果を人間が読める形式 (e.g., "c4, d3") に変換して表示するロジックを追加した。
      - `main.py` に座標を文字列にフォーマットする `format_position` ヘルパー関数を追加した。
      - `main.py` の `game_loop` を修正。ユーザー入力が `'h'` または `'hint'` の場合、`state` の `show_hints` を `True` にしてループを継続させる処理を追加した。それ以外の入力の場合は `show_hints` を `False` に戻し、表示が一時的になるようにした。

### 2.3. コンピュータ対戦機能の実装

- **目的**: プレイヤーがコンピュータと対戦できる機能を追加する。
- **AIロジック**: 最も多くの石を裏返せる手を探索する。
- **手順**:
  1.  **TDD (Test)**: `tests/test_use_cases.py` に `test_find_best_move` を追加。特定の盤面でAIが最適手を選択できるか検証するテストを記述した。テストコードの盤面設定に誤りがあり、2度修正した。
  2.  `pytest` を実行し、`find_best_move` が未実装なため `AttributeError` でテストが失敗することを確認した (レッド)。
  3.  **TDD (Develop)**: `othello/use_cases/game_logic.py` に `find_best_move` 関数を実装。`get_valid_moves`で得られたすべての手について、裏返せる石の数を計算し、最大となるものを選択するロジックを記述した。
  4.  `pytest` を実行し、`test_find_best_move` を含む7つのテストがすべて成功することを確認した (グリーン)。
  5.  **CUI統合**:
      - `othello/entities/game.py` の `GameState` に `game_mode: Literal["PVP", "PVC"]` と `computer_player: Optional[Player]` 属性を追加した。
      - `main.py` に `setup_game` 関数を新規作成し、ゲーム開始前にモード選択と（PVCの場合）プレイヤーの色選択を行えるようにした。`game_loop` はこの関数の戻り値で初期化されるように変更した。
      - `main.py` の `game_loop` を大幅に修正。現在のターンがコンピュータプレイヤーかどうかを判定し、そうであれば `find_best_move` を呼び出して自動で手を処理するロジックを追加した。人間のプレイヤーのターン処理は `handle_human_player_turn` ヘルパー関数に切り出した。
      - `othello/use_cases/game_logic.py` の `handle_move` のシグネチャを `position: Optional[Tuple[int, int]]` に変更し、`position` が `None` の場合にパスとして処理できるようにした。

## 3. 最終確認

- **目的**: v2.0の完成にあたり、すべての機能が正しく動作し、品質が保証されていることを確認する。
- **手順**:

## 4. 追加修正 (レビューフィードバック対応)

- **目的**: 最初のレビューで指摘された重大なバグとドキュメントの不整合を修正し、品質を向上させる。
- **手順**:
  1.  **バグ修正 (`GameState`の状態喪失)**: `othello/use_cases/game_logic.py` の `handle_move` 関数内で、`GameState()` コンストラクタを直接呼び出していた箇所を `state._replace()` に修正。これにより、`game_mode` などの状態が引き継がれないバグを解消した。
  2.  **バグ修正 (ゲーム終了ロジック)**: `handle_move` のロジックをリファクタリングし、プレイヤーがパスした場合でも、関数の最後で必ず `check_game_over` が呼び出されるようにフローを修正した。
  3.  **ドキュメント更新**:
      - `documents/03_内部設計書.md` を、現在のクリーンアーキテクチャの構成とv2.0の新機能（ヒント、AI）を反映した内容に全面的に書き直した。
      - `documents/04_テスト仕様書.md` に、v2.0で追加された `get_valid_moves` と `find_best_move` のテストケースを追記した。
  4.  **リファクタリング**: `main.py` の `game_loop` 内にあった `import time` をファイルの先頭に移動させた。
  5.  `pytest` を再実行し、すべての修正後も全7つのテストが成功することを確認した。
