# CUIオセロアプリケーション 要件定義書

## 1. 概要

本ドキュメントは、CUI（Character User Interface）で動作するオセロアプリケーションの要件を定義する。
本アプリケーションは、関数型プログラミングの原則に基づいて設計・実装され、高い保守性とテスト容易性を目指す。

## 2. 機能要件

### 2.1. ゲームプレイ機能
- 2人のプレイヤー（黒と白）が交互に石を置くことができる。
- ゲーム開始時、盤面の中央に黒と白の石が2つずつ配置されている。
- プレイヤーは、相手の石を挟める場所にのみ石を置くことができる。
- 石を置いたとき、挟んだ相手の石はすべて自分の色の石に変わる。
- どちらかのプレイヤーが石を置ける場所がなくなった場合、パスとなり、相手のターンになる。
- 両者ともに石を置ける場所がなくなった場合、ゲーム終了となる。
- ゲーム終了時、石の数が多いプレイヤーが勝者となる。

### 2.2. CUI機能
- 現在の盤面の状態をCUIで表示する。
- 現在のターンがどちらのプレイヤー（黒か白）かを表示する。
- 各プレイヤーの石の数を表示する。
- プレイヤーが石を置く場所を座標（例: `a1`, `h8`など）で入力できるようにする。
- 無効な場所が入力された場合、エラーメッセージを表示し、再入力を促す。
- ゲーム終了時に、勝者と最終的な石の数を表示する。

## 3. 非機能要件

### 3.1. 開発言語
- Python 3.x系を使用する。

### 3.2. プログラミングパラダイム
- 関数型プログラミングの原則（純粋関数、イミュータビリティなど）に則って実装する。
- 状態の変更は行わず、常に新しい状態を生成するアプローチを採用する。

### 3.3. 実行環境
- 標準的なPCのターミナル（コマンドプロンプト、bashなど）で動作すること。
- 特別なライブラリへの依存は最小限に留める。

### 3.4. テスト
- 各純粋関数に対してユニットテストを作成し、コードカバレッジを高める。
- テストフレームワークとして`pytest`を使用する。
