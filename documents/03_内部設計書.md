# CUIオセロアプリケーション 内部設計書

## 1. 概要

本ドキュメントは、CUIオセロアプリケーションの内部構造と、関数型プログラミングに基づいた実装方針を定義する。

## 2. アーキテクチャ

**Elmアーキテクチャ**（Model-View-Update）を参考に、以下の3つの要素でアプリケーションを構成する。これにより、状態管理とビジネスロジック、UI描画を明確に分離し、副作用を特定の箇所（メインループ）に限定する。

- **Model (状態)**: アプリケーションの状態全体を表現するイミュータブルなデータ構造。
- **Update (更新)**: 現在の状態(Model)と入力(Action)を受け取り、**新しい状態(Model)**を返す純粋関数。副作用を持たない。
- **View (表示)**: 現在の状態(Model)を受け取り、CUIの描画結果（文字列）を返す純粋関数。副作用を持たない。

## 3. データ構造 (Model)

アプリケーションの状態は、すべて単一のイミュータブルな `GameState` オブジェクトで管理する。Pythonの `typing.NamedTuple` または `dataclasses.dataclass(frozen=True)` を用いて実装する。

```python
# othello/core.py

from typing import Tuple, Optional, Literal

# プレイヤーと石の状態
Player = Literal["Black", "White"]
Stone = Optional[Player] # Noneは空きマスを表す
Board = Tuple[Tuple[Stone, ...], ...]

# ゲームの状態全体を表すイミュータブルなデータ構造
class GameState(NamedTuple):
    board: Board
    current_player: Player
    game_over: bool = False
    winner: Optional[Player] = None
    message: str = ""
```

## 4. 主要な純粋関数 (Update)

ゲームのロジックはすべて、`GameState` を受け取って新しい `GameState` を返す純粋関数として実装する。これらの関数は `othello/core.py` に配置する。

- `create_initial_state() -> GameState`:
  - ゲーム開始時の初期状態を生成する。中央に4つの石が配置された盤面、`current_player`が`Black`の状態を返す。

- `handle_move(state: GameState, position: Tuple[int, int]) -> GameState`:
  - プレイヤーの指し手（石を置く位置）を受け取り、ゲームの状態を更新する。
  - **処理の流れ**:
    1. `is_valid_move` で、指定された `position` に石を置けるか検証する。
    2. 置けない場合: `message` にエラーメッセージを設定した新しい `GameState` を返す。
    3. 置ける場合: `_flip_stones` で石を裏返し、新しい盤面を生成する。
    4. プレイヤーを交代させ、`message` をクリアした新しい `GameState` を生成する。
    5. `check_game_over` を呼び出し、ゲーム終了状態か判定し、最終的な `GameState` を返す。

- `is_valid_move(board: Board, player: Player, position: Tuple[int, int]) -> bool`:
  - 指定された位置が、そのプレイヤーにとって有効な手であるかを判定する。
  - マスが空であること、かつ、少なくとも1つ以上の相手の石を裏返せることを確認する。

- `_find_flippable_stones(board: Board, player: Player, position: Tuple[int, int]) -> list[Tuple[int, int]]`:
  - 指定した位置に石を置いた場合に裏返せる、相手の石の座標リストを返す。
  - 8方向（縦横斜め）を探索するロジックを持つ。

- `check_game_over(state: GameState) -> GameState`:
  - 現在のプレイヤーと相手のプレイヤーの両方が、石を置ける場所があるかを確認する。
  - 両者とも置く場所がない場合に `game_over` フラグを `True` にし、石の数を数えて `winner` を決定した新しい `GameState` を返す。
  - どちらか一方のみ置けない場合は、プレイヤーを交代させずにパスとし、相手のターンを継続させる。

## 5. 表示関数 (View)

`GameState` をCUIの文字列に変換する純粋関数。`main.py` に配置する。

- `render_view(state: GameState) -> str`:
  - `GameState` を引数に取り、外部設計書で定義されたレイアウト（盤面、ステータス、メッセージなど）をすべて含んだ文字列を生成して返す。

## 6. メインループ (main.py)

副作用（コンソールへの出力 `print` と、ユーザーからの入力 `input`）はこのメインループに集約する。

```python
# main.py (擬似コード)

def game_loop():
    state = core.create_initial_state()

    while True:
        # 1. View: 現在の状態を描画する
        print(render_view(state))

        # ゲーム終了判定
        if state.game_over:
            break

        # 2. Input: 副作用を伴うユーザー入力を受け取る
        user_input = input(f"Enter your move ({state.current_player}): ")

        # 3. Update: 入力を元に新しい状態を生成する
        # (入力文字列を座標に変換する処理もここで行う)
        state = core.handle_user_input(state, user_input) # handle_user_inputはhandle_moveのラッパー

if __name__ == "__main__":
    game_loop()
```
