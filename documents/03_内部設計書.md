# CUIオセロアプリケーション 内部設計書 (v2.0)

## 1. 概要

本ドキュメントは、CUIオセロアプリケーション v2.0の内部構造と、クリーンアーキテクチャに基づいた実装方針を定義する。

## 2. アーキテクチャ

v2.0では、保守性と拡張性を向上させるため、**クリーンアーキテクチャ**の考え方を採用する。依存性のルールを徹底し、ビジネスロジックがUIや具体的な実装から独立するように設計する。

- **Entities (エンティティ)**:
  - アプリケーションに依存しない、ドメインの核となるビジネスルールとデータ構造。
  - `othello/entities/game.py` に配置。`GameState`, `Player`, `Board` などがこれにあたる。
- **Use Cases (ユースケース)**:
  - アプリケーション固有のビジネスルール。エンティティを操作して、システムの機能を実現する。
  - `othello/use_cases/game_logic.py` に配置。`handle_move`, `get_valid_moves`, `find_best_move` などがこれにあたる。
- **Interface Adapters (インターフェースアダプタ)**:
  - ユースケースとUI（フレームワーク）の間でデータを変換する層。今回はCUIが単純なため、この層は`main.py`内で暗黙的に実装される。
- **Frameworks & Drivers (フレームワークとドライバ)**:
  - UI、データベース、外部ライブラリなど、最も外側の層。
  - `main.py` がCUIとしての責務を担う。

## 3. レイヤー詳細

### 3.1. Entities (`othello/entities/game.py`)

ドメインの核となるデータ構造を定義する。これらはイミュータブル（不変）であり、アプリケーションの他のどの部分からも変更されない。

- `Player`, `Stone`, `Board`: プレイヤー、石、盤面の型定義。
- `GameState(NamedTuple)`: ゲームの状態全体を表現する。v2.0で以下の属性が追加された。
  - `show_hints: bool`: ヒント表示のON/OFFを管理する。
  - `game_mode: Literal["PVP", "PVC"]`: ゲームモードを管理する。
  - `computer_player: Optional[Player]`: PVCモードでのコンピュータの担当色を保持する。

### 3.2. Use Cases (`othello/use_cases/game_logic.py`)

アプリケーションの操作とビジネスロジックを実装する純粋関数の集まり。`GameState`を受け取り、新しい`GameState`を返すことで状態遷移を実現する。

- `create_initial_state() -> GameState`:
  - ゲームの初期状態を生成する。
- `handle_move(state: GameState, position: Optional[Tuple[int, int]]) -> GameState`:
  - プレイヤーの指し手、またはパス (`position`が`None`) を処理し、盤面更新、ターン交代、パス判定を行い、新しい`GameState`を返す。
  - 内部で`is_valid_move`, `_find_flippable_stones`, `_has_any_valid_move`を利用する。
  - 関数の最後で必ず`check_game_over`を呼び出す。
- `check_game_over(state: GameState) -> GameState`:
  - 両プレイヤーが共に有効な手がない場合にゲーム終了と判断し、`game_over`フラグと`winner`を設定した新しい`GameState`を返す。
- **`get_valid_moves(state: GameState) -> list` (v2.0で追加)**:
  - ヒント表示機能のためのユースケース。現在のプレイヤーが石を置けるすべての有効な手の座標リストを返す。
- **`find_best_move(state: GameState) -> Optional[Tuple[int, int]]` (v2.0で追加)**:
  - コンピュータ対戦機能のためのユースケース（AIロジック）。
  - `get_valid_moves`で得られた手の中から、最も多くの石を裏返せる手を探索して返す。

### 3.3. Frameworks - CUI (`main.py`)

副作用（コンソールI/O）をすべてこのファイルに集約する。

- `setup_game() -> GameState`:
  - ゲーム開始時にモード（PVP/PVC）やプレイヤーの色を選択させ、初期`GameState`を生成する。
- `game_loop()`:
  - アプリケーションのメインループ。
  - PVCモードかつコンピュータのターンの場合、`find_best_move`を呼び出して手を決定する。
  - 人間のターンの場合、`input()`で入力を受け付ける。
  - 入力に応じて`handle_move`や`get_valid_moves`などのユースケースを呼び出す。
  - ユースケースから返された新しい`GameState`で状態を更新する。
  - `render_view()`を呼び出してCUIを描画する。
- `render_view(state: GameState) -> str`:
  - `GameState`を受け取り、CUI表示用の文字列を生成する。ヒント表示のロジックも含む。
- `parse_move_input`, `format_position`:
  - ユーザー入力（"c4"）と内部表現（(3, 2)）を相互に変換するヘルパー関数。
